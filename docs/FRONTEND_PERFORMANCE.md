# 前端加载性能

## 2026-09-21：官网入口按路由拆包

官网加载慢的主要代码原因是 `App.tsx` 静态导入了管理布局和几乎全部页面。原入口包含后台表单、API 文档、Markdown 渲染器及菜单使用的完整 Lucide 图标库，访问官网也会下载、解析这些代码。

页面及管理布局现通过 `React.lazy` 按路由加载。`AdminGuard` 仍先完成鉴权，管理布局内的 `Suspense` 让侧边栏在切换页面时保持挂载。`PageLoadBoundary` 在分包下载失败时提供手动刷新入口；不会自动刷新循环，也不向访客展示原始异常。Geist 字体在应用入口统一引入，避免字体随管理布局一起延迟加载。

## 拆包阶段构建测量

以下为本地生产构建，KB 使用十进制，gzip 按每个 JS 文件分别压缩后求和。对照版本保留当前官网内容，使用拆包前的 `App.tsx` 静态导入方式；文件哈希不等同于线上用户报告的 `index-Dp2LjY_4.js`。

| 指标 | 调整前 | 最终版本 |
| --- | ---: | ---: |
| 入口 JS 原始体积 | 2,049,797 B | 224,547 B |
| 入口 JS gzip | 533,664 B | 73,913 B |
| ToB 官网全部初始 JS gzip | 约 534 KB | 约 177 KB |

实验记录：

| 尝试 | 结果 | 决定 |
| --- | --- | --- |
| 页面及管理布局按路由拆分 | ToB 官网初始 JS gzip 约 534 → 164 KB | 保留，后台和文档依赖从官网加载链移出 |
| 补充分包失败恢复界面及统一字体入口 | 最终 ToB 官网初始 JS gzip 约 177 KB | 保留，使用现有 shadcn Button 提供失败恢复，维持字体显示 |

后台菜单的完整图标库仍有超过 500 KB 的独立分包，构建保留对此的警告；官网初次访问不请求该分包。

## 拆包阶段浏览器对照

通过 ego-browser 使用同一浏览器、1440 × 900 视口、禁用缓存、80 ms 延迟、625,000 B/s 下载和 250,000 B/s 上传，交替测量两个本地生产预览服务的 `/aux/tob-home`，每个版本各三次。两边 JS 响应均启用 gzip；未设置 CPU 降速。

| 指标 | 调整前 | 最终版本 |
| --- | --- | --- |
| 入口请求耗时（三次） | 1033 / 1040 / 1041 ms | 246 / 248 / 264 ms |
| 首屏标题 DOM 挂载（三次） | 1285 / 1272 / 1270 ms | 872 / 870 / 886 ms |
| JS 响应压缩后总字节数 | 533,796 B | 178,807 B |
| 初始 JS 请求数 | 1 | 19 |

入口请求耗时取 Resource Timing 的 `duration`，字节数取 JS 资源的 `encodedBodySize`，标题挂载由导航时注入的 `MutationObserver` 记录。标题挂载不是 LCP，入场动画随后继续执行。JS 下载字节数减少约 66.5%；更多分包增加请求数，但在上述条件下仍有明确改善。这些数据不代表线上域名的实际延迟、CDN 命中率或用户设备性能。

浏览器已检查 ToC/ToB 独立和嵌入入口、390 × 844 手机视口、粒子球及字体显示，未发现横向溢出；未登录访问管理首页仍跳转登录，鉴权前不请求管理布局。拦截 API 文档分包可出现恢复界面，解除拦截后点击「重新加载」可恢复文档。

## 体积预算与拆包验证

`pnpm run build` 生成 `dist/.vite/manifest.json` 后自动执行 `scripts/check-bundle-size.mjs`。检查会递归收集并去重入口及目标页面的静态 JS 依赖，防止仅把大文件切成多个小文件就绕过预算；不统计 CSS、字体和后续动态导入。

| 加载范围 | gzip 上限 | 本次结果 |
| --- | ---: | ---: |
| 应用入口及静态依赖 | 100 KiB | 72.2 KiB |
| ToC 官网及入口的静态依赖 | 200 KiB | 172.9 KiB |
| ToB 官网及入口的静态依赖 | 200 KiB | 173.3 KiB |

在 `frontend/` 运行：

```bash
pnpm run typecheck
pnpm run test
pnpm run build
node scripts/check-bundle-size.mjs
```

本次类型检查、全量 41 个测试文件 / 367 项测试及生产构建通过。最终字体入口和加载提示样式调整后，另行通过路由与失败恢复的 18 项测试、类型检查和构建。将预算检查指向拆包前的构建时按预期失败。

复测应使用生产构建、相同配置和上述网络条件，交替运行基线与候选版本；不要用 Vite 开发服务器的模块请求数量衡量发布包。

## 2026-09-21：消除首屏阶段性停顿

进一步录制发现两个问题：路由的「正在加载页面」提示会切换为空白官网外壳，随后导航、文字、粒子球串行入场；同时屏幕下方的全球网络地图在外部 GeoJSON 返回后，同步计算 3,888 个陆地粒子点并挂载大量 SVG 节点。首次记录到地图返回后约 257 ms 的主线程长任务。

官网路由等待态与配置等待态现统一使用 `--aux-homepage-bg`，等待期间不闪现提示文字或默认官网文案。首屏导航、文案和粒子球统一在 450 ms 内淡入；入场只更新透明度，避免和滚动、指针视差同时写入球体变换。

地图的固定陆地底图改为随构建发布的 `src/assets/network-land.svg`，gzip 为 14,793 B。底图仍有原来的 3,888 个点，投影坐标与原版最大差异小于 0.0005 个 SVG 单位（输出保留三位小数），服务器、CDN、客户节点及连线继续由配置驱动。页面不再请求外部 `world-atlas`，也不再执行地理包含关系计算。

沿用上面的浏览器与限速条件，使用本次修改前的拆包版本作基线，交替运行各三次。记录导航后 4.5 秒内的长任务及逐帧有效透明度：

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 标题与粒子球均达到 95% 不透明度 | 3484 / 3241 / 3268 ms | 1187 / 1210 / 1182 ms |
| 前两秒内超过 50 ms 的主线程任务 | 310 / 251 / 196 ms（各一次） | 三次均无 |
| 加载提示文字闪现 | 三次均有 | 三次均无 |

第一项中位数为 3.27 → 1.19 秒，是动画可见程度的测量，不是 LCP。修改后一次记录在 2.66 秒处仍有 66 ms 长任务，其他两次在完整记录区间内无长任务；不据此保证任意设备和网络条件下完全没有掉帧。

当前构建预算结果：入口 72.3 KiB gzip、ToC 172.6 KiB、ToB 172.9 KiB（后两项含入口及静态 JS 依赖，图片不在 JS 预算内）。类型检查、全量 41 个文件 / 367 项测试、生产构建和预算检查通过。ego-browser 已核对地图轮廓及节点、手机视口下四个官网入口和 `prefers-reduced-motion`，未发现横向溢出或内容隐藏。

底图来源为 Natural Earth 公共领域数据，固定使用 `world-atlas@2.0.2`。仅在调整底图、粒子间距或固定地图投影时，在 `frontend/` 运行以下命令，并同步 `TobNetworkMap` 的投影参数：

```bash
node scripts/generate-network-land.mjs
```

生成器使用已有 `d3-geo` 和开发依赖 `topojson-client`，生成时需要网络；普通测试、构建及官网显示均不需要下载外部地理数据。此次额外使用 `gsap-react` 与 `gsap-performance` skill。

## 发布边界

这些优化随 `v0.9.4` 交付。版本 tag 触发构建和发布产物，生产实例仍需管理员主动更新；更新后入口文件哈希和加载链才会变化，无需数据库迁移或环境变量调整。更新后需检查真实域名的资源压缩、缓存响应及访问耗时。当前预算不保证管理页面、动态页内容、图片、字体或 API 的性能。

本次使用 `performance-optimization`、`react-development`、`frontend-ui-engineering`、`ego-browser` 和 `documentation-and-adrs` skill。
